What makes it different

Built for the moment it goes wrong.

Most tools handle the easy failure: the phone drops, show a BRB screen. Keel also handles the hard ones that end streams today.

Crash shield.

If OBS crashes, every platform keeps receiving your Be right back screen while OBS restarts. Keel resumes the broadcast by itself. The stream never ends on viewers.

Built, tested in code

Backup encoder, automatic failover.

Every server takes a second phone, app or Belabox. When the primary drops, viewers stay live on the backup instead of seeing BRB.

Built, tested in code

Switching that understands SRT.

Keel reads packet loss, late packets and round trip time from the link, not only bitrate. A feed at full bitrate that is breaking up still counts as weak.

Built, tested in code

Multistream, isolated.

Twitch, Kick, YouTube and any RTMP or SRT target at once. Each destination reconnects on its own, so one platform having a bad minute never touches the others.

Built, tested in code

Broadcast auto-recover.

If the output stops without anyone pressing stop, Keel restarts it with a short backoff and tells the crew.

Built, tested in code

Rules you can change live.

Thresholds, timings and SRT limits change from the dashboard mid-stream. No restart, no support ticket.

Questions

Straight answers.

Does it work today?

The core path is tested end to end in containers with real OBS: SRT in, switching between LIVE, LOW SIGNAL and BRB, broadcast out, recovery, zero unexpected stops. The new reliability features (backup failover, relay, crash shield, SRT-aware switching, auto-recover) are covered by automated tests and a full end-to-end script that runs on every push. Nothing has been tested yet on a real phone over cellular or against live Twitch, Kick or YouTube. The status page lists exactly what is and is not proven.

What happens to latency?

Keel adds one cloud hop, like every hosted IRL setup. The OBS network buffer defaults to 1 MB, lower than usual, and is adjustable. The relay copies video without re-encoding, so it adds almost nothing. Glass to glass latency has not been measured yet; it is day 3 of the launch plan, and no number will be claimed until it is.

What is a backup encoder?

A second source on the same server: another phone, a second app on a different SIM, or a Belabox. Keel keeps it ready and shows it to viewers only when the primary is worse. When the primary is healthy again for 5 seconds, Keel goes back. You can also pin either one by hand.

What does the crash shield actually do?

OBS sends its program to Keel's relay instead of straight to the platforms. If that program disappears for 3 seconds while you are live, the relay sends an encoded Be right back screen to every platform until OBS is back. Then it switches back to the program and Keel restarts the OBS output if needed.

Can I stream to several platforms at once?

Yes. Add as many destinations as you like. Each one runs separately, reconnects on its own, and can be switched on or off while live. Check each platform's rules on simultaneous streaming before you do.

Can I self host?

Yes. One command sets up a fresh Ubuntu server with HTTPS. See the self-host guide.
